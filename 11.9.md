```python
def create_simulator(args: argparse.Namespace, output_dir: Path) -> Optional[SimulatorAdapter]:
    if args.iterations is None:
        return None

    if args.simulator == "compass":
        # Compass 是 chiplet 数量 + 单 chiplet 架构 + 系统参数

            compass_root=Path(args.compass_root),
            search_config_path=Path(args.search_config),
            exec_config_path=Path(args.exec_config),
            output_root=output_dir,
            search_space=search_space,
        )

    elif args.simulator == "atlas":
        # ATLAS 是单 chip 内部结构：mac_num / vec_num / buffer / core_num / frequency / dram

            system_yaml_path=Path(args.atlas_system_yaml) if args.atlas_system_yaml else None,
```

### 为什么

`search_space` 会经 `schema()["search_space"]` 进三个 agent 的 prompt（`model_level.py:38`、`solution.py:93`），也是所有硬件工具的唯一候选值来源。不改的话，LLM 看到的候选集是 `compute_units / buffer_size / chiplet_type / dram_bw / ...`，而 `atlas_config.py` 只读 `mac_num / vec_num / buffer_size / buffer_read_bw / buffer_write_bw / core_num / frequency / dram_config_path`。

**后果是"静默错"**：LLM 每轮都在改 `compute_units`、`chiplet_type`，这些字段在 ATLAS 侧根本不读，评估结果不变，但日志显示"改进成功/失败"，形成噪声闭环。

### 注意

**不要动 `create_existing_adapter`（L215-229）里的那处 `make_hardware_search_space`。** 那处喂给 `GenericFileEvaluationAdapter`，靠 `--from-existing` 走分析模式，本次不涉及。

## 1.2 `search_space.py` 修 ATLAS 常量的两个 bug

**文件**：`chiplet_tuner/core/search_space.py`
**位置**：L105-143

### 现状（两处硬 bug）

```python
ATLAS_DEFAULT_HARDWARE_SEARCH_SPACE : Dict[str, Any] = {
    "design_space_kind": "atlas_chip_yaml",
    "compute_scale": None,
    "array_shape":[],
    "num_chiplet_candidates": [],
    ...
    "system_params" : SYSTEM_PARAM_SEARCH_SPACE,
    ...
}
```

### 改成

**第一处（L108）：单数改复数**

```python
    "array_shapes": [],
```

**第二处（L116）：换成 ATLAS 自己的系统参数**

```python
    "system_params": ATLAS_SYSTEM_PARAM_SEARCH_SPACE,
```

### 为什么

**`array_shape` → `array_shapes`**：`array_shape_candidates`（L208）读的是

```python
raw_shapes = search_space.get("array_shapes", search_space.get("shape_candidates", DEFAULT_ARRAY_SHAPES))
```

写成单数时永远 miss，直接回退到 Compass 的 `DEFAULT_ARRAY_SHAPES`（L13-23，1×1 到 16×16）。**所以即使把 ATLAS 空间接上了，`materialize_hardware` 依然会给 ATLAS 硬件算 `num_chiplets / chip_y / chip_x`。**

**`SYSTEM_PARAM_SEARCH_SPACE` → `ATLAS_SYSTEM_PARAM_SEARCH_SPACE`**：后者的值才是 `ATLAS_SYSTEM_PARAM_SEARCH_SPACE`（L93-103，含 `dram_config_path` 的 5 个候选）。不改的话，`dram_config_path` 永远无法被枚举和校验——LLM 写个不存在的 yaml 名字会一路传到 `ATLAS/hardware_parser.py` 才炸。

### 注意（重要联动）

改成 `array_shapes: []` 后，`shape_candidate_for_request`（L261-263）在**没有硬件形状**时会抛：

```python
if not candidates:
    raise ValueError("No legal array_shape candidates can be derived from the design space.")
```

所以 **这一处不能单独上线**，必须等 [2.1](#21-search_spacepy-normalize-加短路) 的短路生效。如果中途想先跑 Compass 回归，就先只改 `system_params`，`array_shapes` 留到最后。

### 验证

```bash
python3 -c "
from chiplet_tuner.core.search_space import ATLAS_DEFAULT_HARDWARE_SEARCH_SPACE as S
assert S['array_shapes'] == [], S['array_shapes']
assert 'dram_config_path' in S['system_params'], list(S['system_params'])
print('OK')
"
```

## 1.3 `search_space.py` 系统参数动态枚举

**文件**：`chiplet_tuner/core/search_space.py`
**位置**：L181-185

### 现状

```python
def all_system_param_candidates(search_space: Mapping[str, Any]) -> Dict[str, List[Any]]:
    return {
        key: system_param_candidates(search_space, key)
        for key in ["dram_bw", "nop_bw", "micro_batch", "tensor_parall"]
    }
```

### 改成

```python
_LEGACY_SYSTEM_PARAM_KEYS = ("dram_bw", "nop_bw", "micro_batch", "tensor_parall")


def all_system_param_candidates(search_space: Mapping[str, Any]) -> Dict[str, List[Any]]:
    """Enumerate every system-level parameter declared by the design space.

    The four Compass keys are kept first so that MaterializeHardware output
    ordering (and therefore hardware_fingerprint) stays byte-stable for
    existing Compass history databases.
    """

    system_params = search_space.get("system_params", {})
    keys: List[str] = list(_LEGACY_SYSTEM_PARAM_KEYS)
    if isinstance(system_params, Mapping):
        for key in system_params:
            if key not in keys:
                keys.append(key)
    return {key: system_param_candidates(search_space, key) for key in keys}
```

### 为什么

四个 Compass 键是硬编码的，导致 `dram_config_path` 永远进不了这个函数。改完后：

- `materialize_hardware`（L355）会遍历到 `dram_config_path`——但 ATLAS 走 [2.1](#21-search_spacepy-normalize-加短路) 的短路，不会执行到那里，所以对 Compass 无影响（Compass 的 `system_params` 只有那 4 个键）。
- `_search_space_position`（`analysis_tools.py:1966`）会自动把 `dram_config_path` 的位置算出来。
- `normalize_hardware_to_design_space`（L434）的 `system_params` 循环也会覆盖到它。

### 注意

**兼容键必须在前。** `materialize_hardware` 是按 dict 顺序写入的，顺序变化会让 Compass 硬件的 JSON key 顺序变，进而**改变 `hardware_fingerprint`**，导致历史 RAG 记录与本次指纹对不上。

### 验证

```bash

    all_system_param_candidates, DEFAULT_HARDWARE_SEARCH_SPACE,
    ATLAS_DEFAULT_HARDWARE_SEARCH_SPACE)
assert list(all_system_param_candidates(DEFAULT_HARDWARE_SEARCH_SPACE))[:4] == [
    'dram_bw','nop_bw','micro_batch','tensor_parall']
assert 'dram_config_path' in all_system_param_candidates(ATLAS_DEFAULT_HARDWARE_SEARCH_SPACE)
print('OK')
```

## 2.1 `search_space.py` normalize 加短路

**文件**：`chiplet_tuner/core/search_space.py`
**位置**：L412-423

### 现状

```python
def normalize_hardware_to_design_space(
    proposed: Mapping[str, Any],
    current: Mapping[str, Any],
    search_space: Optional[Mapping[str, Any]] = None,
) -> Tuple[Dict[str, Any], List[str]]:
    search_space = search_space or DEFAULT_HARDWARE_SEARCH_SPACE
    notes: List[str] = []
    if not isinstance(proposed, Mapping):
        return copy.deepcopy(dict(current)), ["proposal is not a hardware object; kept current hardware"]

    shape_request = _requested_shape(proposed)
    shape_candidate = shape_candidate_for_request(
        ...
    )
```

### 改成

在 `if not isinstance(proposed, Mapping):` 那条 `return` 之后、`shape_request = _requested_shape(proposed)` 之前，插入两行：

```python
    if not isinstance(proposed, Mapping):
        return copy.deepcopy(dict(current)), ["proposal is not a hardware object; kept current hardware"]

    # Field-based design spaces (ATLAS and future adapters) do not have chiplet
    # arrays or derived chip_x/chip_y. Route them to the field-level clamp so
    # materialize_hardware() never injects Compass-only keys into their hardware.
    if search_space.get("design_space_kind") != "explicit_count_per_chiplet":
        return _normalize_by_field_candidates(proposed, current, search_space)

    shape_request = _requested_shape(proposed)
```

### 为什么

`materialize_hardware`（L349-408）对 ATLAS 硬件做三件不需要的事：

| 行 | 动作 | ATLAS 后果 |
|---|---|---|
| L351-353 | 写 `num_chiplets/chip_y/chip_x` | 多 3 个无意义字段，进指纹 |
| L355-360 | 对 4 个 Compass 系统参数 `coerce` | 多 4 个字段，且 `None` 会回退成 `candidates[0]` |
| L400-408 | 重建 `chiplets[]` | 多 1 个大数组，进 RAG 向量 |

`coerce_to_candidates`（L509-537）对 `value=None` 的行为是：

```python
if value in candidates: return value
numeric = _numeric_candidates(candidates)
if numeric:
    source = float(value)      # None → TypeError → 跳过
    ...
if notes is not None:
    notes.append(...)
return copy.deepcopy(candidates[0])   # ← 拿走第一个候选
```

净效果：一份干净的 ATLAS 硬件经过一次 `normalize` 后变成

```json
{"mac_num": 8192, "vec_num": 512, "core_num": 16, ...,
 "num_chiplets": 1, "chip_y": 1, "chip_x": 1,
 "dram_bw": 16, "nop_bw": 32, "micro_batch": 1, "tensor_parall": 4,
 "chiplets": [{"type": "ws", "buffer_size": 2048, "compute_units": 1024, "macs": "[4,4,8,8]"}]}
```

这 9 个字段 ATLAS 完全忽略，但：
1. **参与 `hardware_fingerprint`**（`vector_store.py:36-37` 对整个 dict 做 sha256）
2. **参与 RAG 双通道向量**（`vector_store.py:40-66` 的 `summarize_hardware` 会读 `chiplets`）
3. **参与 `best_hardware.json` 和 commit 的 before/after 比较**

也就是说：去重判断和 RAG 检索是在一个"半 Compass 半 ATLAS"的混合对象上做的，而这个对象既不是 LLM 提的、也不是 ATLAS 仿真的。

### 注意（插入位置只有 1 行窗口）

- 插到 `if not isinstance(...)` **之前** → `proposed` 未校验就进新函数
- 插到 `shape_request` **之后** → 会先因为 1.2 的 `array_shapes: []` 抛 `ValueError`

判断条件用 `!= "explicit_count_per_chiplet"` 而不是 `== "atlas_chip_yaml"`，这样以后加第三个仿真器时默认走"纯字段 clamp"这条更保守的路径。

```python
# meaning for a simulator whose design space is field-based (e.g. ATLAS).
# They are dropped rather than forwarded, so they never enter
# hardware_fingerprint() or the RAG hardware embedding.
_IGNORED_NON_SIMULATOR_FIELDS = frozenset(
    {
        "num_chiplets",
        "chip_x",
        "chip_y",
        "chiplets",
        "shape",
        "array_shape",
        "chip_shape",
        "chip_size",
        "chip_spec",
        "compute_spec",
        "per_chiplet_specs",
        "chiplet_specs",
        "chiplet_spec_strategy",
        "resource_strategy",
        "chiplet_type_strategy",
        "type_strategy",
        "chiplet_type_fill",
        "fill_chiplet_type",
        "uniform_chiplet_type",
        "compute_unit_fill",
        "buffer_size_fill",
        "uniform_compute_units",
        "uniform_buffer_size",
    }
)


def tunable_field_names(search_space: Mapping[str, Any]) -> List[str]:
    """Collect tunable hardware field names from tunable_categories, in order.

    Falls back to the legacy chiplet-oriented field names when the design space
    does not declare categories, so callers always get a non-empty list.
    """

    names: List[str] = []
    categories = search_space.get("tunable_categories", {})
    if isinstance(categories, Mapping):
        for spec in categories.values():
            if not isinstance(spec, Mapping):
                continue
            parameters = spec.get("parameters", [])
            if not isinstance(parameters, Sequence) or isinstance(parameters, (str, bytes)):
                continue
            for field in parameters:
                key = str(field)
                if key and key not in names:
                    names.append(key)
    if not names:
        names = list(_LEGACY_TUNABLE_FIELDS)
    return names


def _normalize_by_field_candidates(
    proposed: Mapping[str, Any],
    current: Mapping[str, Any],
    search_space: Mapping[str, Any],
) -> Tuple[Dict[str, Any], List[str]]:
    """Clamp proposed tunable fields against their candidate sets.

    Unlike materialize_hardware(), this never injects derived or simulator-
    specific keys. The returned hardware therefore contains exactly the fields
    the proposer asked for, which keeps hardware_fingerprint() and the RAG
    hardware embedding aligned with what was actually evaluated.
    """

    notes: List[str] = []
    updated = copy.deepcopy(dict(current))
    tunable = tunable_field_names(search_space)
    ragged_keys = set(tunable) | _IGNORED_NON_SIMULATOR_FIELDS

    for field in tunable:
        if field not in proposed:
            continue
        value = proposed[field]
        if value is None:
            notes.append(f"kept current {field} because proposed value is null")
            continue
        candidates = system_param_candidates(search_space, field)
        updated[field] = coerce_to_candidates(
            value,
            current.get(field),
            candidates,
            key=field,
            notes=notes,
        )

    for field, value in proposed.items():
        if field in ragged_keys:
            continue
        notes.append(f"kept non-tunable field {field} as provided (no design-space rule)")
        updated[field] = value

    return updated, notes
```

### 与文件现有风格的对齐点

- `notes: List[str] = []` + `notes.append(...)`，与 `normalize_hardware_to_design_space`（L418、L447、L470）一致
- 返回 `Tuple[Dict[str, Any], List[str]]`，与 L416 的签名一致
- `copy.deepcopy(dict(current))`，与 L420 一致
- 复用 `system_param_candidates`（L171）和 `coerce_to_candidates`（L509），不新造 clamp 逻辑
- `Sequence` / `Mapping` 判断沿用 `chip_type_candidates`（L198）、`system_param_candidates`（L173）的写法

### 三个刻意的行为选择

1. **`value is None` 时跳过，不 clamp**。`coerce_to_candidates` 对 `None` 会走到 L531/L536，把 `dram_config_path` 换成第一个 yaml。那不是 LLM 的意图，是噪声。
2. **未知字段透传而不是丢弃**（`kept non-tunable field ...`）。这样 `power` / `area` 这类装饰字段不会丢；同时 `_IGNORED_NON_SIMULATOR_FIELDS` 里的 Compass 残留会被静默丢掉。两条规则合起来刚好覆盖 A3 的全部注入源。
3. **`tunable_field_names` 空时回退 `_LEGACY_TUNABLE_FIELDS`**。防止有人传一个没有 `tunable_categories` 的裸 search_space 时函数返回空列表，导致 `make_exploration_move` 又一个字段都试不了。

> ⚠️ 命名一致性：跨模块要用公开名 `tunable_field_names`（不带下划线），不要写成 `_tunable_field_names`。`tools/analysis_tools.py` 和 `agents/solution.py` 都会 import 它。

## 6.3 文件级验收脚本

存成 `/tmp/verify_atlas_run.py`：

```python
"""File-level verification for a post-fix ATLAS run. Usage: python3 verify_atlas_run.py <run_dir>"""
import json
import sys
from pathlib import Path

run = Path(sys.argv[1]).resolve()
ATLAS_FIELDS = {
    "mac_num", "vec_num", "buffer_size", "buffer_read_bw",
    "buffer_write_bw", "core_num", "frequency", "dram_config_path",
}
COMPASS_LEAK = {"num_chiplets", "chip_x", "chip_y", "chiplets",
                "dram_bw", "nop_bw", "micro_batch", "tensor_parall"}

problems = []

iters = sorted(p for p in run.glob("iter_*") if p.is_dir())
if not iters:
    sys.exit(f"no iter_* under {run}")

baseline_hw = json.loads((iters[0] / "hardware.json").read_text())

for it in iters:
    hw_path = it / "hardware.json"
    if not hw_path.exists():
        problems.append(f"{it.name}: hardware.json missing")
        continue
    hw = json.loads(hw_path.read_text())
    keys = set(hw)

    leaked = keys & COMPASS_LEAK
    if leaked:
        problems.append(f"{it.name}: Compass fields leaked into hardware: {sorted(leaked)}")

    missing = ATLAS_FIELDS - keys
    if missing:
        problems.append(f"{it.name}: ATLAS fields missing: {sorted(missing)}")

    if keys != set(baseline_hw) and it.name != iters[0].name:
        problems.append(
            f"{it.name}: key set drifted from baseline "
            f"(+{sorted(keys - set(baseline_hw))} -{sorted(set(baseline_hw) - keys)})"
        )

    detail = it / "exec_latency_detail.json"
    if detail.exists():
        d = json.loads(detail.read_text())
        if "_meta" in d:
            problems.append(f"{it.name}: '_meta' at detail top level")
        for core, entries in d.items():
            if not isinstance(entries, list):
                problems.append(
                    f"{it.name}: detail['{core}'] is {type(entries).__name__}, expected list")
                continue
            for e in entries:
                vals = [e.get(k) for k in ("calcTime", "dramTime")]
                if all(isinstance(v, (int, float)) and v > 0 for v in vals):
                    problems.append(
                        f"{it.name}: detail still has nonzero calcTime/dramTime "
                        f"({vals}) — looks fabricated")
                    break

    meta = it / "exec_detail_meta.json"
    if detail.exists() and not meta.exists():
        problems.append(f"{it.name}: exec_detail_meta.json missing")

    trace = it / "analysis" / "agent_trace.json"
    if trace.exists() and it.name != iters[0].name:
        t = json.loads(trace.read_text())
        actions = ((t.get("proposal") or {}).get("actions")) or []
        if not actions:
            problems.append(f"{it.name}: proposal.actions empty")

md = run / "tuning_metrics_table.md"
if md.exists():
    rows = [l for l in md.read_text().splitlines() if l.startswith("| iter")]
    if rows and all(l.rstrip().endswith("|  |") for l in rows):
        problems.append("tuning_metrics_table.md: all Applied Change cells empty")

print(f"checked {len(iters)} iteration dirs under {run.name}")
if problems:
    print(f"\n{len(problems)} problem(s):")
    for p in problems:
        print(f"  - {p}")
    sys.exit(1)
print("artifact-level verification passed")
```

## 6.4 三层验收的关系

| 层 | 手段 | 能抓到 | 抓不到 |

# 7. 本次不做的事

| 项 | 为什么不在这里做 |

| **B2** `summarize_hardware_config` 显示 ATLAS 字段 | 1.3 的动态枚举已经让 `_search_space_position` 覆盖到 ATLAS 字段，但 `_summarize_hardware`（L2435）里的 `chiplets[]` 假设还在。这是"显示不完整"而非"显示错误"，优先级低于上面三步 |

| **C4** `design_space_kind` 被读取 | 2.1 已经让它被读取了，这条实际已解决 |
| **C5** `tp_size/ep_size` 进设计空间 | 这是**扩展设计空间**，属于新功能不是修 bug。加了会改变 ATLAS 的搜索维度，需要配套改 `atlas_config.build_system_yaml` 和 system yaml 生成 |

| `_compare_metrics` 彻底去掉 mc | 会改变所有历史 run 的语义，需要一次数据迁移决策 |
